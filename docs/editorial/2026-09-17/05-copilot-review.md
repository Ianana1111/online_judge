# 官方快報｜AI 寫完之後誰來驗收？GitHub 示範把 diff、終端機與預覽放在一起

AI 產生程式碼的速度愈來愈快，接下來的問題是：我們怎麼確認它真的完成任務？GitHub 本週的官方教學，把焦點放在產生程式之後的檢查流程。

*judge. 官方快報 · 2026/09/17｜消息日期：2026/09/10*

## 新聞現場

GitHub 在 9 月 10 日發布 Copilot app 入門教學，示範如何在同一個工作環境查看 **diff、執行終端機指令、用瀏覽器預覽介面**，再繼續調整程式。這是一篇工具使用教學，並不是新的模型效能評測，也不代表當天才首次推出所有功能。[查看 GitHub 官方教學](https://github.blog/ai-and-ml/github-copilot/github-copilot-app-for-beginners-using-the-diff-terminal-and-browser/)

## judge. 觀點：能解釋改動，才比較接近真正學會

把這個流程放進刷題練習，可以變成三件事：先用自己的話說明解法，再找出程式的關鍵判斷，最後設計一個可能讓它失敗的輸入。

例如 AI 建議使用二分搜尋，就試著回答：搜尋範圍是什麼？條件為什麼有單調性？邊界更新會不會讓迴圈停不下來？如果只能照貼程式，還說不清這幾點，可以先請工具只給提示，再自己完成。這是本站提出的學習方法，並非官方教學的測試結論。
