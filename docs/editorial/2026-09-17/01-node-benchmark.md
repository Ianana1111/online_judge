# 官方快報｜Node.js 26.9 登場：程式跑得快，怎麼拿出證據？

Node.js 昨天推出 26.9.0，這次值得寫程式的人留意的，是新增的效能量測工具。當我們說「這個解法比較快」，接下來就該有數據。

*judge. 官方快報 · 2026/09/17｜消息日期：2026/09/16*

## 新聞現場

Node.js 官方發布 **26.9.0 Current**，重點包含 `node:bench`、Histogram 的 `meanCI` API，以及 Web Workers 支援。發布紀錄也明確記載，`node:bench` 仍需實驗性旗標 `--experimental-bench`；這次是 Current 版本，不能把它當成已進入 LTS 的公告。[查看 Node.js 發布紀錄](https://nodejs.org/en/blog/release/v26.9.0)

## judge. 觀點：一次跑贏，還不能下結論

刷題時，兩份都 AC 的程式可能只差幾毫秒。這個差距有時來自資料規模，有時受到啟動成本、執行環境或其他工作影響。比較之前，先確認答案一致，再固定輸入、執行多輪，觀察分布，會比只挑最快的一次更有說服力。

可以做一個小實驗：用陣列逐一尋找元素，再改成適合該題條件的集合查找。把輸入從一千筆增加到十萬筆，記錄時間與記憶體。你會更容易分辨，改善來自演算法，還是單次測量的波動。上述是本站提出的練習方法，不是這次發布的效能保證。
