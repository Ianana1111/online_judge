# Deployment changes required before rollout

Operational checklist for this release. The owner-authorized production rollout completed on September 13 after a restricted local backup and isolated restore/migration rehearsal; see [the deployment record](deployment-20260913.md) for exactly what was executed. The remaining README gates continue to track broader launch-readiness work.

1. Back up PostgreSQL and demonstrate a restore into an isolated database. Test migrations through `20260912050000_tourist_guide_answer` there. Verify row counts, historical subscription entitlements, canonical school aliases and existing published content. New ContentRevision indexes include partial unique constraints and target CHECK constraints.
2. Deploy API + web together for the new paginated `/posts` and `/discussions` contracts. Pause community writes during the transition. Existing public content is retained; pending revisions are never stored in the public body/title fields. Old school links must be resent because new challenges require a stored nonce hash. Existing school verification timestamps are preserved.
3. All old access tokens lack the required session identifier and will require users to log in again. Verify cookies/CORS/CSRF for the actual web/API domains. Generate separate random secrets of at least 32 bytes for each required auth purpose. Set HTTPS `WEB_ORIGIN` and `API_ORIGIN`, plus an explicit ECPAY_ENV (sandbox in staging; real merchant credentials only in production).
4. Configure `TRUSTED_PROXY_CIDRS` from the deployment provider's documented socket-peer addresses before using X-Real-IP. Unauthenticated rate limits default to the actual socket peer; authenticated limits use the account ID. Never set an arbitrary hop count or trust headers from every address. Direct API access must not bypass the trusted edge.
5. Rebuild the Vercel judge snapshot with `setpriv` and `pkill` prerequisites, and repeat the isolation fixture suite against the actual SDK/snapshot. The worker must not use the old unrestricted snapshot. Compiler output limit is 64 MiB; run stdout/stderr limits are 8 MiB each. Temporary paths are cleared between cases; this is not a claim of full independent-VM isolation per test case.
6. The migration image no longer creates demo/admin accounts. Local seeding requires ALLOW_LOCAL_DEMO_SEED=1 and a local database, and refuses NODE_ENV=production. Audit pre-existing bootstrap accounts before launch and rotate any that still use demo credentials. Never print production passwords.
7. Refund actions that time out or otherwise return ambiguous outcomes stay in NEEDS_REVIEW. The administrator Billing page now exposes all states, paging and retained records; `/billing/admin/refunds` returns `{ items, nextCursor, counts }` instead of a bare array. Reconcile with the gateway before attempting another external action. Preserve existing promised historical refund terms. The [runbook](refund-reconciliation.md) identifies the still-required audited resolution command and live rehearsal.
8. Account deletion preserves the existing anti-reuse school-email ledger but removes its user relationship. Review retention and operational access controls before release; consider a keyed fingerprint migration to reduce retained personal data. Do not expose this ledger to browser APIs.

9. Coordinate judge data migrations with the updated worker: UVa 10150 becomes SPECIAL and requires the built-in shortest-path checker. Two new content migrations append reviewed cases and narrowly correct the known UVa 10099 answer. Compare a staging mirror with the inventory before applying; do not overwrite unrelated test cases or rerun the original seed scripts.
10. UVa remote jobs now use a Redis-wide concurrency of 1 and one start per 8 seconds across replicas. Use one dedicated bot account for this queue; scripts that bypass the queue must not submit concurrently. Production workers validate INTERNAL_SERVICE_TOKEN and explicit database/Redis/API configuration before consuming jobs.
11. Fonts are bundled locally with their OFL notices, removing Google Fonts network requests during builds and page loads. The API and web must be deployed together for the lightweight `/posts/sitemap` endpoint. Split into a sitemap index before reaching 50,000 URLs.
12. Google deletion reauthentication now checks the current account's linked subject without issuing a new login session. Confirm both matching/wrong-account choices and cancellation on the actual Google OAuth deployment, including cookie behavior on Safari. External token/user-info requests have a 10-second timeout.

Application rollback requires compatible schema readers. Do not drop new payment/revision/outbox data in an emergency rollback; pause affected writes, restore the previous compatible app, and reconcile events before resuming. A tested recovery drill is still required.
