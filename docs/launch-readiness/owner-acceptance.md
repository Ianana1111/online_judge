# 正式金流、信箱與 Apple Pay：站長驗收清單

查證日期：2026-09-15。正式環境目前設定為綠界 production，金流憑證、Resend 寄信設定與寄件網域 `judge.tw` 均有配置。這只能證明設定存在；本次沒有進行實卡扣款、退款或寄出真實郵件，也尚未啟用 Apple Pay。

## 1. 真實金流驗收

請準備自己控制的普通測試帳號、一張可線上付款的信用卡，以及綠界商家後台權限。使用沒有 Pro、學生優惠或管理員權限的帳號，才能觀察付款前後的權益差異。操作前記錄付款頁當下顯示的方案、金額、優惠與續訂條款；價格可能受活動影響。

| 你操作 | 工程端核對 | 通過條件 |
| --- | --- | --- |
| 先進入付款，再取消返回 | 訂單與權益 | 沒有成功扣款，沒有新增付費權益 |
| 同意付款頁的實際金額後，完成一次真實首扣及銀行驗證 | 商家訂單編號、金額、回呼驗章、付款狀態與會員到期日 | 綠界與本站紀錄一致；只入帳、延長權益一次 |
| 重新整理訂單／付款結果頁 | 回呼與畫面冪等性 | 不因重整或回呼重送重複延長權益 |
| 取消自動續訂 | 綠界定期定額取消狀態及本站紀錄 | 後續不再續扣，已付期間依既有條款保留 |
| 依網站既有政策提出退款，再由管理員處理 | 退款金額、綠界結果與最終銀行紀錄 | 不重複退款；權益依政策調整。取消續訂本身不是退款 |
| 等待真正續扣，或先與綠界約定可接受的驗收方式 | 續扣交易與權益銜接 | 首扣成功不能代替續扣驗收 |

管理員退款等敏感操作前，先到設定的安全性頁面啟用驗證器並保存復原碼。實際退款費用、入帳／退回時程以商家合約和銀行紀錄為準。提供訂單編號與操作結果即可；不需在對話提供卡號、CVV、OTP、密碼或金流金鑰。[綠界定期定額](https://developers.ecpay.com.tw/2868/)、[退款作業](https://developers.ecpay.com.tw/2885/)。

## 2. 真實信箱驗收

請準備自己可以收信的 Gmail／Outlook 信箱，以及要驗證的學校信箱。另確認 Resend 後台 `judge.tw` 的網域狀態與 DNS 驗證通過；有 API key 不等於寄送或收件成功。[Resend 網域驗證](https://resend.com/docs/dashboard/domains/introduction)。

本次唯讀呼叫 Resend 網域清單得到 `401 restricted_api_key`，提供者明確表示正式金鑰僅有寄信權限。這不是無效金鑰的證據；保留此權限範圍，請由後台確認網域狀態，不為了查詢而擴大正式金鑰權限。仍未寄出真實驗收信。[Resend 錯誤類型](https://resend.com/docs/api-reference/errors)。

1. 用密碼註冊的普通帳號發出驗證信，確認主收件匣／垃圾郵件、寄件人、連結網域和手機閱讀呈現，完成驗證後確認站內狀態更新。
2. 執行忘記密碼，收到信後設定新密碼；確認新密碼可登入、舊密碼失效、舊登入狀態依撤銷機制失效。Google 專用帳號應使用 Google 登入流程。
3. 再開同一個已使用連結，確認不能重複操作；過期連結需要重新申請。工程端比對投遞狀態、退信與錯誤日誌，畫面顯示「已寄出」不能當作收件證據。
4. 用真正的學校信箱完成學校驗證，確認帳號的學校和優惠權益。163 筆名錄對應 158 所機構是名稱涵蓋證據，仍不能證明每個學校信箱可收件。

請只回報測試的時間、信箱服務商與成功／失敗現象；驗證信完整 token 不需貼在對話裡。

## 3. Apple Pay 需要先做什麼

目前商品是信用卡月／年自動續訂。建議第一階段另設「單次購買固定期間、不自動續訂」的 Apple Pay 商品；是否採用仍需商品決策。Apple Pay 一般能力、綠界信用卡續扣能力與本商家的 Apple Pay 續扣資格是不同問題，需取得綠界對所選方案的確認。

1. **商家開通與報價：**登入綠界後台確認 Apple Pay 是否已開通、可用的串接方案、費率、退款與撥款條件。綠界目前客服頁將 Apple Pay 列為各會員類型可用，但站內付 Web 串接頁仍列特約申請流程；請以本商家的所選介接與後台／客服回覆確認，不要一概認定所有 Apple Pay 都必須升級特約。[會員可用服務](https://support.ecpay.com.tw/25120/)、[站內付設定](https://developers.ecpay.com.tw/57359/)。
2. **選擇付款方式：**現有全方位金流可評估跳轉綠界付款頁，使用 Apple Pay 的單次付款流程；改為網站內直接付款則需要另一套 SDK／訂單整合，不能只換按鈕。[全方位 Apple Pay](https://developers.ecpay.com.tw/7328/)。
3. **如採站內付：**從綠界「系統設定 → Apple Pay 介接設定」取得自己的網域驗證檔；工程端部署到 `https://judge.tw/.well-known/apple-developer-merchantid-domain-association` 並確認直接回傳正確檔案，你再回後台完成網域驗證。跳轉綠界付款頁的流程是否另需驗證本站網域，依該方案要求處理，不直接套用站內付規則。[網域驗證步驟](https://developers.ecpay.com.tw/57359/)。
4. **Apple 帳號與裝置：**綠界 Web 版 Apple Pay 文件說明此方案不需自行申請 Apple Developer 帳號；這不涵蓋日後原生 iOS App 的上架。準備支援的 Apple 裝置及已加入 Wallet 的卡片，親自驗證付款、取消與退款。支援瀏覽器需依串接方案檢查；現行全方位文件已有跨瀏覽器 QR 流程，不能一律用 Safari 限制。[綠界 Web 付款](https://developers.ecpay.com.tw/9040/)、[全方位支援方式](https://developers.ecpay.com.tw/7328/)。

若未來上架原生 iOS App 並在 App 內銷售數位功能／訂閱，需另外依銷售地區與適用例外檢查 StoreKit／App 內購買要求；網站 Apple Pay 並不能直接替代它。[Apple 審查規範](https://developer.apple.com/app-store/review/guidelines/#in-app-purchase)。

工程端可完成訂單狀態、回呼驗章、金額核對、冪等性、權益、防重複付款、退款與不支援裝置的處理；商家合約、實際銀行授權與收信確認需要站長控制的帳號／裝置操作。
