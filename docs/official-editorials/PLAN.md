# 全題庫官方詳解與評測驗收計畫

建立日期：2026-09-21。以本輪正式題庫唯讀快照為範圍，逐題追蹤；歷史盤點為 430 題，不能把既有 83 份候選程式驗證檔視為全題庫驗收。

## 交付內容

1. 每題在「我的提交紀錄」右側新增「官方詳解」。支援手機、鍵盤操作、深淺色、載入／失敗／尚未發布狀態；詳解按需取得，不預載答案到題目 JSON。
2. 每篇以繁體中文撰寫：題意與合法限制、關鍵觀察、演算法步驟、小型範例推演、正確性論證、時間／空間複雜度、完整可提交程式、逐段程式解說、易錯點。參考解必須與顯示／複製的程式逐位元一致。
3. 優先使用 C++17；若合法中間計算需要精確大整數，可選擇本站支援且實際驗證的 Python 3，例如 10268。每篇標明程式語言與選擇原因，不依賴 Sandbox 未安裝的函式庫。閱讀資格暫採所有使用者可讀，正在作答該題所屬虛擬測驗的帳號由伺服器暫時封鎖詳解，考後開放；依使用者回覆調整。此限制只管理站內正常流程，不能阻止使用者取得公開題目的站外解答。
4. 每題有獨立、可重跑的驗收紀錄。發布要求題目版本、詳解內容、程式碼、編譯／執行設定及測資指紋相符。題意、範例、測資或評測設定變動後，既有驗證立即失效，重新驗證後再發布。

## 工作階段與順序

### 1. 正式資料盤點與基準

- 唯讀匯出所有題目、公開範例、隱藏測資、資源限制、checker 與考試關聯；不匯出帳號、訂單或使用者程式。
- 保存加密／受限存取的既有備份策略與本輪 SHA-256 快照；公開報告只含計數、問題分類與指紋，不放隱藏輸入／答案。
- 對照最新的 PDF 範例修正（145、10222、11005）及 441 多筆資料回歸，確認實際資料，不能只因修正腳本存在就標記完成。
- 建立逐題清單：尚未撰寫、草稿、參考解待驗、測資待補、待覆核、可發布、已發布／版本已失效。列出外部 judge 依賴與缺失。

### 2. 詳解基礎功能與驗證工具

- 獨立的詳解資料模型與讀取 API；不經由討論投稿冒充官方內容。
- 發布工具以驗證報告為必要輸入，拒絕來源指紋不符、未跑完測資、正解失敗、錯解存活、待人工釐清的報告。保留既有內容與發布時間，支援回溯。
- 題目頁加入詳解分頁、程式碼複製及清楚的章節排版。詳解與編輯器草稿互不覆蓋。
- 測驗限制在 API 端生效；跨帳號查詢快取隔離，拒絕以另一個網址直接讀取目前測驗的答案。
- 建立可續跑的全題庫 audit 命令，每一題獨立保存證據，失敗不會讓其他題目的已完成證據遺失。

### 3. 優先題與第一批完整實作

- 先處理最近出錯題、格式／多解／浮點題，再處理 CPE 基礎題與考前必刷題。
- 第一批必須貫穿完整流程：題意覆核 → 詳解 → 正解 → 獨立 oracle／小規模暴力 → 合法測資 → 常見錯解 → Run／Submit → UI。
- 先證明流程可用，再用相同標準逐批完成其餘題目；不以通用模板或未驗證程式填滿完成率。

### 4. 全題庫逐題完成

- 每批依演算法與測資風險分組。相似題可共用工具，不共用未經題意確認的輸入限制或輸出規則。
- 對每題完整執行所有現有範例與全部隱藏測資，記錄每一筆結果，不在第一個 WA 就把其餘測資略過。
- 為每題補足獨立驗證：小範圍窮舉、不同實作／不同演算法、數學不變量、語義 checker 或可追溯的人工推導。單純由同一份參考解產生答案再驗自己不算獨立驗證。
- 每題完成詳解覆核、邊界覆蓋矩陣及針對性的錯解驗收，逐批發布已完成內容；最後清單不得有未處理項目。

### 5. 上線前與部署後驗收

- 完整型別／lint／單元／資料庫／API／瀏覽器測試，以及全題庫程式驗證均須通過。
- 離線 Linux sandbox 使用正式 compile/run/checker 實作；另外以正式 Vercel 工具鏈驗證時間、記憶體與所有發布參考解，不能把 macOS 本機 AC 當成正式 judge AC。
- Run 與 Submit 對同一份程式、同一份合法輸入、同一個 checker 設定比較；公開範例結果須一致。自訂輸入沒有標準答案時只報執行輸出，不捏造 AC。
- 備份後套用可重播、比對前值的內容修正，不重置正式題庫、不重評既有使用者提交，除非另有明確需要及範圍。
- 核對部署 commit、資料庫版本、詳解發布數、Run／Submit 健康及可回復版本，再宣告完成。

## 「測資剛剛好」的驗收標準

- **合法**：遵守原題輸入限制；沒有題外條件、未定義輸入、超規模測資或錯誤答案。
- **充分**：涵蓋最小值、最大值、單筆與多筆、EOF／終止符、重複／並列／全相同、排序方向、溢位與精度，以及圖不連通、無解、多解等該題適用的邊界。
- **可辨識錯誤**：針對至少兩種實際可能的錯解設計反例；簡單題若不適用，逐題記錄理由，不為湊數捏造需求。CE／SE 不算成功攔下錯誤演算法。
- **不誤殺**：題意允許的不同正解、合法格式與合理複雜度應通過；浮點誤差與多解使用正確 checker。對格式的要求以題意為準，不能一律刪掉所有空白來掩蓋錯誤。
- **效能有依據**：限制依題目規模、合理演算法及正式工具鏈實測校準；記錄安全餘裕，避免用偶發執行時間判定演算法錯誤。

## 完成定義

以最新正式題庫為分母，每題都有完整詳解、可提交程式、全部測資執行證據、獨立答案驗證、邊界與錯解覆蓋、Run／Submit 一致性及已發布版本紀錄。任何未完成或不確定的項目都明列，不能把部分通過描述成全題庫已完成。有限測試不能證明所有錯誤程式都會被拒絕，但每個已知缺口必須有對應的反例與回歸證據。
