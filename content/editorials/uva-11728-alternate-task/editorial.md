## 題意與限制

給一個正整數 S≤1000，找正整數 n，使 n 的所有正因數總和等於 S。因數包含 1 與 n 本身；如果有多個候選，輸出最大的 n，若不存在輸出 −1。以零結束，輸出包含從一開始的案例編號。這題是在反查因數和，不是直接求 S 的因數。

## 解題思路

因數和至少包含 n 本身，所以查詢 S≤1000 時，任何候選 n 都不會超過 1000。這讓我們可以反向預處理整個值域：先用篩法同時計算每個 n 的完整因數和，再建立「因數和 → 最大原數」的查表，所有查詢便成為 O(1)。

因為 n 自己就是因數，所以因數和至少為 n；若 S≤1000，候選 n 絕不會超過 1000。先用類似篩法的方式：對每個 divisor，把它加到所有倍數的 sum 裡。這樣每個 sum[n] 都是 n 的完整因數和。

接著讓 n 從小到大走，若 sum[n]≤1000，就寫入 largest[sum[n]]=n。相同因數和出現多次時，後面較大的 n 會覆蓋前面的，最後自然保留最大解。沒有被寫過的位置維持 −1。

## 範例推演

n=1 只有因數 1，所以 S=1 的答案為 1。n=6 的因數和為 1+2+3+6=12，但 n=11 的因數和也是 1+11=12，因此查詢 S=12 必須回傳較大的 11。S=2 找不到任何正整數的因數和等於它，應印 −1。

## 正確性

篩法對每個 divisor d，只把 d 加到它的正倍數，因此 sum[n] 被加入的值恰好是且只有 n 的全部正因數。所有可能解都在 1 至 S≤1000，所以候選範圍完整。第二遍依 n 遞增覆蓋相同索引，使 largest[S] 在結束時保留全部解中最大的一個；從未出現的 S 維持不存在標記。

## 複雜度

令上界 U=1000，篩法總工作量為 U/1+U/2+…+U/U，時間 O(U log U)，反表 O(U)，空間 O(U)。預處理只做一次，每個查詢 O(1)。

## 常見錯誤

- 只加真因數而漏掉 n 自己。
- 遇到第一個解就停止，沒有選最大值。
- 因為 S=1 很小而直接判無解，漏掉 n=1。
- 只搜尋質數，忽略合數可能有相同因數和。
- 用零初始化結果卻把零當成合法答案。
- 因數和超過 1000 時仍拿來索引反表，造成越界。
