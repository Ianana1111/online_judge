## 題意與限制

兩個長度皆為 N 的嚴格遞增陣列，由二次多項式給定：`A[i]=p*i*i+q*i+r`、`B[i]=x*i*i+y*i+z`，索引從 0 到 N−1。六個係數皆為正整數，所有數值保證能以有號 64 位元整數保存。

請從兩個陣列合計 2N 個元素中，找出第 N 小的值。不同陣列中相同的值仍然算兩個元素，不能先去重。測試筆數為 1～100，N 為 1～10⁷；不適合真的生成並排序兩千萬個元素。

## 解題思路

這題真正需要的不是兩個陣列的內容，而是一條能把合併結果切成「前 N 個」與「其餘元素」的界線。只要決定左半部從 A 拿多少個，B 的數量就跟著確定，因此原本兩個分割點其實只剩一個可二分的變數。

想像在兩個已排序陣列中各切一刀，讓左側合計恰好有 N 個元素。若從 A 取前 `takeA` 個，便必須從 B 取前 `takeB=N-takeA` 個。

這個分割正確的條件是：左側所有元素都不大於右側所有元素。由於各陣列本身已遞增，只需檢查兩個跨陣列邊界：`aLeft <= bRight`，以及 `bLeft <= aRight`。

若 `aLeft > bRight`，表示 A 左邊取太多，應減少 `takeA`；若 `bLeft > aRight`，表示 A 取太少，應增加 `takeA`。因此可在 0～N 之間二分搜尋 `takeA`。

找到合法分割時，左側恰有 N 個最小元素，第 N 小就是左側最大值 `max(aLeft,bLeft)`。邊界某側沒有元素時，分別用最小或最大整數作為負、正無限大的哨兵，不讀取陣列之外的位置。

## 範例推演

題面例子 A=`[2,6,14]`、B=`[3,6,11]`，N=3。從 A 取一個、B 取兩個，左側為 `[2]` 與 `[3,6]`，右側為 `[6,14]` 與 `[11]`。兩個跨邊界比較均成立，因此答案是左側最大值 6。

合併後實際順序為 `2,3,6,6,11,14`，第 3 小確實是 6。兩個 6 均要保留；若去重，後續排名就會改變。

## 正確性

若分割符合兩個跨界條件，再加上各陣列自身的排序性，即可知道左側每個元素都不大於右側任一元素。左側元素數恰為 N，所以其最大值就是第 N 小，包含重複值的情況也成立。

若 `aLeft > bRight`，再增加 A 的取值數量只會使 aLeft 不變或變大，同時 B 取值變少使 bRight 不變或變小，違反條件不可能改善。因此合法答案只能在較小的 `takeA`。另一種違反條件可對稱推得必須增加 `takeA`。二分搜尋每次只刪除不可能區間，最後會找到合法分割並回傳正確答案。

## 複雜度

每次二分迴圈只計算四個邊界值，每個二次多項式都能 O(1) 求值。時間 O(log N)，額外空間 O(1)，不需儲存完整 A、B，也不需建立合併陣列。

## 常見錯誤

- 把「第 N 小」當成零起始索引 N，實際取到第 N+1 小。
- 將兩個陣列的重複值去重，改變題目要求的排名。
- 只比較兩個左邊界大小，卻沒有檢查左側與另一陣列右側的關係。
- 分割點在 0 或 N 時仍存取 −1、N 索引，沒有處理空的一側。
- 用 32 位元計算多項式的乘積或輸出答案，雖然 N 本身能放進 `int`，元素值卻可能大很多。
