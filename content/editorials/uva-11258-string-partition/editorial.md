## 題意與限制

每筆至多二百位數字，要切成一串不含前導零的非負 32 位有號整數，使總和最大。單獨零合法，多位數零開頭不合法。每段值必須在零至 2147483647，但所有段加起來的總和可以超過 32 位。案例數至多五百。

## 解題思路

每個切割方案都能按「第一段選到哪裡」分類，因此很自然地把後面的最佳答案交給 DP。關鍵限制還幫我們把轉移壓得很小：一個合法正整數最多十位，所以每個起點只需嘗試最多十個結尾。前導零則不是一般枚舉的一部分；看到零時，唯一合法第一段就是單獨的 0。

定義 best[i] 為從位置 i 到尾端的最大切割總和，空後綴 best[n]=0。若 digits[i] 是零，這段只能取單獨零，答案等於 best[i+1]。否則枚舉下一段終點 j，逐位累積 value，若不超過上限，就以 value+best[j+1] 更新。

合法正整數最多十位，所以最多查看十個終點；超過上限便停止，因為再加一位只會更大。i 從尾端往前走，轉移用到的後綴都已算好。不要貪心總是取最長段，切割點會影響後面能組成的大整數。

## 範例推演

字串 2147483647 可整段取為上限值；2147483648 則不可整段，必須切開，最佳為 214748364 與 8，總和 214748372。000 只能拆成三個零，答案零。很多段接近上限時，總和可達數百億，所以 best 必須用 long long。

## 正確性

任意合法切割都有唯一第一段 i..j，剩下部分是一個合法後綴切割。枚舉涵蓋所有合法第一段；固定此段時，後續若未使用最佳切割便可替換成更大的總和，因此最佳值一定是 value+best[j+1] 的最大。以空後綴為基底向前歸納即可得到整串最佳值。零開頭只允許單字元，另行轉移精確排除非法前導零。

## 複雜度

每個起點最多十個終點，時間 O(10L)，DP 空間 O(L)，L≤200。累積最多十位數仍可安全放進 64 位整數，再與 32 位上限比較，不能先用 int 累積到溢位才檢查。

## 常見錯誤

- 把總和也限制為 32 位，導致正確大答案溢位。
- 允許 01 或 000 作單一整數。
- 把上限比較寫成 >=，排除合法的 2147483647。
- 每次只取最長合法前綴，沒有比較不同切法。
- value 用 int，檢查上限前就已溢位。
