在直線上走過某個位置就能立即收集硬幣，因此已收集的硬幣一定是一段連續區間。沒有必要記任意子集合，只要記區間兩端與現在停在哪一端。

left[l]、right[l] 在每個區間長度那一輪，代表收完該區間並停在左／右端的最早時間。從單顆硬幣開始，時間為 0；若期限不大於 0，連起點都收不到。−1 表示這個狀態不可能。

擴到左端 l 時，可以從 [l+1,r] 的左端走一小段，或從右端跨過整個區間；擴到右端同理。只保留早於新硬幣期限的抵達時間，等於期限已來不及。兩個候選取較早的，因為同一區間、同一端点越早抵達，未來任何走法都不會更差。

由短區間往長區間計算，每輪 l 從小到大，使 l+1 的舊資料仍保留，l 的舊資料也在覆寫前先讀完，所以只需兩排 O(n) 空間。基本時間 O(n²)。C 使用 128 位元中間距離；Java 在加法前比較剩餘期限，並偵測座標差的 long 溢位，避免 64 位元極值繞回成很小的正時間。

Python 額外用必要條件篩選起點：起點必須在每顆硬幣的期限可達區間內。起點可選在第一顆實際收集的硬幣上，因為提早從那裡出發只會更好。任何路程至少跨過全部跨度，再加起點到較近端的距離；如果一條完整掃過兩端的路程符合全部期限且剛好達到這個下界，就可直接返回，否則仍執行完整區間 DP。這個捷徑不把可行性當成猜測。


Python 的完整 DP 只存至少有一端可行的區間，下一輪從它們向左右各擴一顆。兩端都不可行的狀態不可能復活，所以略過它們不影響答案。期限緊、可行起點少的大規模資料常只保留很少區間，避免仍掃過大量必定失敗的位置；最壞界仍是 O(n²) 時間、每輪 O(n) 空間。


還可提前排除「已抵達，但未來必定趕不上」的端點。對左側尚未收集的硬幣，必要条件是 time<min(deadline[i]+position[i])−現在位置；右側則是 time<min(deadline[i]−position[i])+現在位置。前綴／後綴最小值讓每個端點只需 O(1) 檢查。這只是必要條件，通過後仍繼續 DP；未通過的狀態則不可能完成，安全丟棄。
