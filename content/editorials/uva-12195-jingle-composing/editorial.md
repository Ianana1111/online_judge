## 題意與限制

每首曲子由 / 包住並分隔小節，每小節至少一個音符。W、H、Q、E、S、T、X 的時值依序為 1、1/2、1/4、1/8、1/16、1/32、1/64；小節總長度恰好為一才算正確。曲子長度 3 至 200，單獨一行 * 結束輸入。要求每首曲子有幾個正確小節。

## 解題思路

如果直接用浮點數累加 `1/2`、`1/8` 等時值，這題剛好可能仍能工作，卻把一個原本完全離散的問題變成了近似比較。更穩定的推導方式是先找所有分母的最小公倍數；它們都是二的次方，最大分母 64 本身就是最小公倍數。整首曲子的判定於是變成「每節整數總和是否等於 64」，也自然區分不足、剛好與超過。

所有分母都是 64 的因數，所以把時值全部乘 64，轉為 64、32、16、8、4、2、1。之後只需要整數加法與 sum==64，沒有近似比較問題。遇到音符就加時值，遇到 / 就結算前一小節並把 sum 歸零。

曲子的第一個 / 前面沒有音符，sum 為零，不會誤計；最後一個 / 會完成最後一節結算。只接受等於 64，超過也不合法。即使某節提早超過 64，仍須繼續走到分隔符，避免影響後續小節。

## 範例推演

`/HH/QQQQ/W/HW/` 的前面三節分別是 32+32、四個 16、64，全部正確；最後一節是 32+64=96，不能計入，所以答案三。64 個 X 恰好是一，63 個 X 則不足，65 個 X 則超過，三者必須能區分。

## 正確性

每個音符都以相同倍率 64 轉換，故小節原時值等於一的充要條件就是轉換後總和等於 64。掃描過程的 sum 始終等於最近一個 / 後所有音符的轉換時值和。每到下一個 / 就精確評估該節一次並重設，因此每個合法小節被計入一次，其他小節完全不計。

## 複雜度

曲子長度 L≤200，每個字元處理一次，時間 O(L)，使用固定七種音符表與計數器，額外空間 O(1)，字串儲存 O(L)。

## 常見錯誤

- 使用 >=64，把過長小節也算對。
- 忘記在 / 後歸零，累積到下一小節。
- 將 X 誤認為 1/32，漏掉最短音符。
- 未結算最後一節。
- 把開頭 / 當作一個正確空小節。
