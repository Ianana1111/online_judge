## 題意與限制

每行給出兩支軍隊的人數，求兩者差距，輸出非負整數。兩個數字可能依任意順序出現，讀到 EOF，沒有測試組數或數值終止行。原題明定人數不大於 2^32，因此合法範圍包含 4294967296，不能只用 signed int。

## 解題思路

把較大人數減去較小人數，就得到絕對差。輸入和差值都使用 long long：它能表示完整 0 到 2^32 的範圍，也能安全表示相減結果。使用 max(a,b)−min(a,b) 可以直接看出結果非負，不需要先形成負數再取絕對值。

雖背景故事說 Hashmat 的人數不多於對手，輸入段落明確允許兩軍順序互換，所以不可固定第二個減第一個。while(cin>>a>>b) 在讀完完整一對才計算，直到檔案結束；0 0 是一般案例，答案零，之後仍要繼續。

## 範例推演

輸入 10、12 得二，輸入 12、10 也得二。兩軍相同時差為零。0 與 4294967296 的差正是 4294967296，比 signed int 最大值還大，也超過無符號三十二位元最大值 4294967295；因此包含這個端點的測試可抓出過窄的型別。

## 正確性

若 a≥b，max(a,b)=a、min(a,b)=b，程式輸出 a−b；若 a<b，輸出 b−a。兩種情況互斥且涵蓋全部輸入，結果都等於絕對差。合法值皆非負且最多 2^32，所以較大減較小仍落在 0 到 2^32，long long 可精確表示，沒有溢位或捨入。EOF 控制每組完整讀取並輸出一次，也不會將合法零值誤認為終止條件。

## 複雜度

每組做一次比較與減法，時間 O(1)、額外空間 O(1)，整份輸入有 Q 行時總時間 O(Q)。只保留當前兩數，不需要把整份資料讀入陣列，也不需要任意精度或浮點數。

## 常見錯誤

- 使用三十二位元 signed int，無法讀入超過 2^31−1 的合法人數。
- 改成 unsigned int 仍容納不了恰好 2^32。
- 永遠輸出 b−a，輸入反向時得到負值。
- 把第一個人數當成測試組數。
- 遇到 0 0 就停止，漏掉其後案例。
