## 題意與限制

將彈珠上的整數由小到大排列後，對每個查詢回答該數字第一次出現的位置，位置從 1 開始；不存在就輸出 not found。題目有多組資料，只有 N 和 Q 同時為 0 才結束。所有輸入數字介於 0 與 10000，案例數少於 65，因此零也是合法的彈珠值和查詢值。

## 解題思路

先排序整個彈珠陣列，再對每次查詢使用 lower_bound，找第一個「大於或等於 x」的位置。若位置有效且值恰好等於 x，它就是第一顆編號為 x 的彈珠；若已走到陣列尾端或值比 x 大，就表示 x 不存在。

必須找的是排序後的第一個位置，不是原始輸入位置，也不是任何一顆匹配的彈珠。重複的值仍然要保留，因為它們會影響後面數字的位置。lower_bound 可以一次處理第一個匹配及不存在兩種情況，不需要找到後再向左逐一回退。

## 範例推演

彈珠是 `5 1 3 3 1`，排序後得到 `1 1 3 3 5`。查詢 3 的 lower_bound 指向索引 2，轉成題目的位置就是 3。若查詢 2，lower_bound 同樣指向第一個 3，但值不等於 2，所以應回報不存在。

查詢 6 會得到 end，此時不能解參考。空陣列搭配非零查詢數也以同樣方式回報不存在，只有 `0 0` 才是終止資料。

## 正確性

排序使所有小於 x 的值出現在所有大於或等於 x 的值之前。lower_bound 回傳兩者的分界，因此其左邊沒有任何 x。若分界上的值等於 x，這個位置必然是第一個 x；若大於 x，後面也不可能有 x；若分界是 end，整個陣列都小於 x。三種情況恰好涵蓋存在與不存在的可能，並以索引加一得到所需位置。

## 複雜度

排序花費 O(N log N)，每次二分查詢為 O(log(N+1))，讀寫 Q 筆查詢仍需 O(Q)，總時間為 O(N log(N+1) + Q log(N+2))。陣列需要 O(N) 空間，查詢可隨讀隨答。

## 常見錯誤

- 使用 upper_bound，拿到最後一顆之後的位置。
- 去除重複值，改變所有後續排名。
- 找到插入點就當成找到 x，沒有檢查值是否相等。
- 解參考 end，或忘記把零起算索引轉成一開始的位置。
- 任一個 N 或 Q 是零就結束，提早漏掉合法資料。
