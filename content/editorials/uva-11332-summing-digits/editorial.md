## 題意與限制

對正整數 n，把每個十進位數字相加，再對新的總和重複相同操作，直到只剩一位數，輸出最後的數。每筆 n 最多 2,000,000,000，讀到 0 表示整份輸入結束，終止的 0 不需要處理。

這題加的是數字本身，與 Happy Number 的「數字平方和」不同。也不能只做一次數字總和，因為第一次結果仍可能有兩位以上。

## 解題思路

使用兩層迴圈：外層負責重複做「數字總和」，只要目前數值至少 10，就還需要再做一次；內層負責取出所有十進位數字。

內層每次用 `% 10` 取得個位數，加到 sum，再用 `/ 10` 移除已處理的個位數。當目前值被消耗成 0，表示原本的所有位數已處理完，就把 sum 當成下一輪的值。

輸入本來就是 1～9 時，外層迴圈直接略過，原值就是答案。每次進行新一輪總和時，sum 都必須重新歸零。

## 範例推演

題目例子 1234567892 的第一次數字總和為 47，仍然不是一位數；第二次為 `4+7=11`；第三次為 `1+1=2`，此時才停止，輸出 2。

另一個容易漏掉的例子是 99：第一次為 18，第二次為 9。若只做一次，會錯誤輸出 18；若直接輸出 n 除以 9 的餘數，則會錯誤輸出 0。對正整數而言，正確的最終數字一定介於 1 到 9。

## 正確性

內層每一步取出目前最低位數並將它移除，因此停止時，sum 恰好是該輪原數字所有十進位數字的總和。將 value 更新成 sum，就完成題目定義的一次轉換。

若 value 至少有兩位，它的數字總和一定比原值小：高位數在原數字中的位權至少為 10，但在數字總和中位權降為 1。因此正整數序列會持續下降，直到進入 1～9。這些一位數再次做數字總和仍是自己，所以停止時的值就是題目定義的 g(n)。

## 複雜度

設初始數字有 D 位，第一輪需 O(D) 時間；後續總和的位數迅速縮小，總計仍為 O(D)，也就是 O(log n)。只使用數個整數變數，額外空間 O(1)。

## 常見錯誤

- 只執行一次數字總和，沒有繼續直到一位數。
- 每輪忘記把 sum 清零，把不同輪次的數字累加在一起。
- 套用 n%9 卻沒有處理正倍數的答案應為 9。
- 將終止符 0 也輸出，或把一位數誤判成還需要特殊處理。
