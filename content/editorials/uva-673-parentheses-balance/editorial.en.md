# Match each closing bracket with the most recent opener

## Problem and constraints

Each test case is one line of at most 128 characters containing only `()[]`. Decide whether it is generated by valid concatenation and same-type nesting. The empty string is explicitly valid and occupies a real test-case line, so input must preserve empty lines after the initial count.

## Building the approach

Push every opening parenthesis or bracket. A closing symbol must match the most recent still-open symbol, the stack top. If the stack is empty or the types differ, the string is invalid; otherwise pop the pair. After scanning, require the stack to be empty so no opener remains unmatched.

Counts alone cannot enforce nesting order. For example, `([)]` has equal counts of both types but closes the outer parenthesis while the bracket is still inside. The LIFO stack records exactly which inner interval must close next. An empty line performs no operations and ends with the initially empty stack, correctly returning `Yes`.

## Walkthrough

`([])[]` pushes `(` and `[`, closes them in reverse order, then matches the final pair, so it is valid. In `([)]`, `)` encounters `[` on top and fails. `(()` never mismatches during scanning but leaves one `(` afterward, so it is invalid.

## Why it works

After every processed prefix, the stack from bottom to top contains exactly its unmatched opening symbols from outermost to innermost. A valid closing symbol must close that innermost opener, so a missing or different top proves invalidity; a correct pop preserves the invariant. If processing finishes with an empty stack, every opener and closer forms a correctly nested or concatenated pair, which is sufficient for validity.

## Complexity

For line length `L`, each character is pushed or popped at most once, giving `O(L)` time and `O(L)` stack space.

## Common mistakes

- Reading with `cin >> line` and skipping an empty valid case.
- Comparing only total opening and closing counts.
- Accessing the stack top before checking emptiness.
- Accepting a prefix with no mismatch but leftover openers.
- Treating parentheses and square brackets as interchangeable.
