## 題意與限制

輸入一連串正整數，每個數最多 1,000,000，最多 250,000 個，讀到 0 結束（0 不處理）。對每個 N 輸出 `f91(N) = 答案`。f91 的定義是：N ≥ 101 時回傳 N − 10；N ≤ 100 時回傳 f91(f91(N + 11))。

## 解題思路

照定義直接寫遞迴是可以算出答案的，但每個小於等於 100 的 N 都會展開很多層呼叫。更好的做法是先把這個函數「算透」，再用一行公式回答。

N ≥ 101 的情況很單純，就是 N − 10。關鍵在 N ≤ 100：先試幾個值。f91(100) = f91(f91(111)) = f91(101) = 91；f91(99) = f91(f91(110)) = f91(100) = 91。可以觀察到，只要 N 落在 91 到 100，內層加 11 後會超過 100，減 10 又回到比原本大 1 的位置，最後一路爬到 100，再得到 91。

N 比 91 更小時，內層的 N + 11 仍然 ≤ 100，會繼續往上加，直到進入 91 到 101 這一段，之後同樣收斂到 91。所以結論是：N ≤ 100 時答案永遠是 91，N ≥ 101 時答案是 N − 10。

這題最多有 25 萬筆輸入，真正要注意的是輸入輸出速度：一次讀完、一次輸出，比每行都 flush 快得多。

## 範例推演

N = 500 ≥ 101，答案 500 − 10 = 490，輸出 `f91(500) = 490`。N = 91 ≤ 100，答案 91，輸出 `f91(91) = 91`。讀到 0 就停止，不輸出任何東西。

再看兩個邊界：N = 100 得到 91，N = 101 得到 91（101 − 10），兩邊剛好接得上；N = 1,000,000 得到 999,990。

## 正確性

對 N ≥ 101，定義直接給出 N − 10。對 91 ≤ N ≤ 100，用 N 由大到小歸納：N = 100 時已算出 91；若 N + 1 的答案是 91，則 f91(N) = f91(f91(N + 11)) = f91(N + 1) = 91，因為 N + 11 ≥ 102，內層等於 N + 1。對 N ≤ 90，N + 11 ≤ 101：若 N + 11 ≤ 100，依歸納假設內層是 91，再算 f91(91) = 91；若 N + 11 = 101，內層是 91，同樣得到 91。因此所有 N ≤ 100 的答案都是 91。

## 複雜度

每個查詢 O(1)，總時間 O(Q)，Q 最多 250,000。輸出緩衝最多約數 MB，額外記憶體與輸出大小同階。

## 常見錯誤

- 把邊界寫成 N < 100，導致 f91(100) 錯算成 90。
- 把結尾的 0 也當成一筆資料輸出。
- 直接遞迴且每行都 `endl`，在 25 萬筆輸入下變慢。
- 輸出格式少了等號兩側的空白，或括號位置不對。
