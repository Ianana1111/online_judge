集合裡的元素也是集合，如果每次都直接遞迴展開，巢狀很深時會很麻煩。可以替每種不同集合內容分配唯一 ID：內容相同就用同一個 ID，於是外層集合只需存一組整數 ID。

這個編號方式為什麼保留集合相等？空集合先有固定 ID；之後新集合的元素都是已知集合的 ID，兩個新集合只要這組 ID 相同，元素集合也逐一相同。因此由空集合逐步建立時，結構相等就等價於 ID 相等。

PUSH 放空集合 ID，DUP 複製堆疊頂 ID。其他指令先彈出 a，再彈 b。UNION／INTERSECT 合併或取共同元素；ADD 則是「把集合 a 本身當成一個元素放進 b」，所以要插入 ID a，不能把 a 裡面的元素攤平進去。做完把結果 intern 成 ID 再推回堆疊。

已 intern 的集合不可改動，否則舊 ID 的意義會偷偷改變。C 使用排序、去重的整數陣列，雙指標做聯集與交集，hash 桶只用來加速查找；遇到 hash 相同仍完整比較內容，碰撞不影響正確性。Python 用 frozenset，Java 保存不可修改的集合，每次運算另建結果。

每一步輸出最上面集合的「直接元素數」，不是所有巢狀元素加總。每組最後印 ***，即使操作數為零也要印。令 U 為不同集合數、s 為操作中的元素數，集合合併與內容 hash 比較需 O(s) 左右，總空間是所有已 intern 集合的直接成員數之和。
