## 題意與限制

電腦的堆疊元素都是集合，集合裡面也可以放集合。PUSH 放入空集合，DUP 複製頂端，UNION 與 INTERSECT 取兩集合聯集、交集；ADD 把先彈出的整個集合作為一個元素加入第二個集合。每次操作後輸出頂端集合基數，每個案例後印三顆星。T 可為零，操作數也可為零，最多五組、每組兩千次，保證不會空堆疊彈出。

## 解題思路

這題真正難的地方不是堆疊，而是「集合可以成為另一個集合的元素」。若直接複製整棵巢狀結構，DUP 與後續操作會讓資料快速膨脹；若只存指標，又不能用指標判斷兩個內容相同的集合相等。關鍵觀察是：一個集合只由它包含哪些子集合決定。因此可以先替每個已知子集合取編號，再把「一組子集合編號」當作上一層集合的完整身分。這樣由內而外建立，就把遞迴結構化成可比較的整數集合。

不直接以遞迴物件保存所有巢狀內容，而替每個不同集合配置唯一整數 ID。某集合本身用 set<int> 保存其元素的 ID；若兩個集合內容相同，查表會得到同一 ID。空集合也只有一個固定 ID，堆疊保存這些 ID 即可。

聯集與交集直接對元素 ID 操作。ADD 必須將第一個集合的 ID a 插入第二個集合 values[b]，不是把 values[a] 的元素攤平。所有新結果先建立副本，再 intern 查表，舊集合不可被改動，否則 DUP 共享 ID 會被連帶影響。

## 範例推演

PUSH、DUP 後堆上有兩個空集合，ADD 得到含空集合的集合，大小一。此時 DUP、ADD 得到 {空集合,{空集合}}，大小二。若把 ADD 寫成 UNION，第一步兩個空集合的聯集仍是空，立刻和正確答案不同。重複加入同一個元素也只算一次，因為是集合而非列表。

## 正確性

歸納已建立的每個 ID 都唯一代表一個集合。空集合基底成立；新集合的每個元素 ID 已有確定含義，因此相同 ID 集合恰代表相同巢狀集合，查表可正確合併相等者並区分不等者。五個指令分別依定義操作這些 ID，ADD 插入整體身分，聯集交集操作成員，故結果語意不變。輸出 set 大小正好是頂層元素數，不會錯算深層節點總量。

## 複雜度

設操作數 Q、已登錄集合數 S≤Q+1、最大單一集合元素數 K≤Q。集合操作及複製約 O(K log K)，標準化查表最壞 O(K log S)，總體可保守估 O(QK(log K+log S))；儲存所有集合至多 O(SK)，堆疊 O(Q)。ID 避免展開重複巢狀子結構。

## 常見錯誤

- ADD 寫成 UNION，把一個集合攤成多個元素。
- 顛倒 ADD 的兩個彈出順序。
- 以指標位置判相等，沒有合併相同內容。
- 原地修改已登錄集合，破壞共用 ID 的含義。
- 零次操作忘記輸出案例結尾 ***。
